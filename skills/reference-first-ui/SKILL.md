## Purpose

Use this skill to prevent blank-slate UI work when curated references already exist.
The goal is to reuse, adapt, or compose from proven references before inventing a new pattern.

## When to Use

Use this skill when the task involves:

- New screens, pages, panels, dashboards, or flows
- UI components or component families
- Landing pages or marketing pages
- Onboarding, settings, or empty states
- Visual redesigns or component refactors

## Required Reference Pass

Before building from scratch, inspect:

1. `ui.shadcn.com`
2. `21st.dev`
3. `componentry.dev`
4. `styles.refero.design`

If a reference already solves the problem, adapt it instead of rebuilding it.

## Workflow

1. Identify the UI goal and component type.
2. Search the curated references above.
3. Compare at least two viable patterns when the task is visual or user-facing.
4. Reuse the closest valid pattern with the smallest safe adaptation.
5. Only design from scratch when no suitable reference exists.
6. Record which references were consulted and why they were or were not reused.

## Output Rules

- Favor reusable blocks over one-off custom UI.
- Prefer consistency with the repo's current design language.
- Keep a short record of the reference sources used.
- Do not claim a reference was used if it was not checked.
